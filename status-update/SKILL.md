# Status Update

Write an update that busy people can read in 30 seconds and know what it means for them and whether they need to do anything.

## Step 1: Work out the basics

From what the user shared, identify:

- **Who's reading**: boss, team, client, senior leadership, or a mixed group
- **Where it's going**: email, chat message (Slack, Teams, and so on), or a longer written report
- **The ask**: what the user needs from readers, if anything, and by when

If the channel isn't stated, guess from the audience: leadership and clients usually get email, the team usually gets a chat message. Mention your guess.

## Step 2: Pick what matters to this audience

Choose the 3 to 5 things this audience cares about. Leave out the rest. A boss wants progress, risks, and decisions needed. A team wants what changes for them. A client wants what they'll get and when.

## Step 3: Put the ask first

- If readers need to do something, say it in the first two lines, with a deadline: "**Need from you:** approval on the budget by Thursday."
- If nothing is needed, say so: "_FYI, no action needed._"

## Step 4: Replace jargon

Swap internal terms and acronyms for plain words the audience will understand. List the swaps you made below the draft so the user can check them.

## Formats

**Email**

```text
Subject: [Topic]: [outcome in a few words]

Hi [name/team],

[One line: what this is and why they're getting it.]

Need from you: [ask + deadline]   (or: FYI, no action needed)

- [Key point 1]
- [Key point 2]
- [Key point 3]

What this means for you: [1-2 sentences tailored to them]

Next: [what happens next and when]

[Sign-off]
```

**Chat message**

```text
*[Headline in one line]*
• [Point 1]
• [Point 2]
• [Point 3]
*Need from you:* [ask + deadline]   (or: _FYI, no action needed_)
```

**Written report for leadership**
Summary in 3 to 4 lines first, then the ask, then no more than 3 short sections of detail. Formal tone, no emoji.

## Rules

- Never overstate progress or invent results. If something is behind, say so plainly with the new date.
- Keep bad news near the top, not hidden at the bottom.
- If an `email-voice-profile.md` exists, write emails in the user's voice.
- If this continues an earlier update, link to it or mention it in one line ("Following up on last week's update...").
